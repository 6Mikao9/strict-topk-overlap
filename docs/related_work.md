# 与 PRR 的关系及实验边界

核查日期：2026-11-03。研究来源为用户的《PRR 严格 Top-K 修正研究构想》。本项目验证混合保存与撤销的可行性，不据此宣称完整系统复现或新颖性已成立。

## 集合覆盖与严格选择语义

令当前正式选择集合为 A，历史信息预测集合为 P。PRR 原文明确保留 P 中不属于 A 的块，仅补算 A 中不属于 P 的块。因此其合并结果对应 attention(A ∪ P)，而严格 Top-K 基线对应 attention(A)。覆盖全部正式选择块并不等于具有相同 attention 输出；新增块通常会同时改变 softmax 分母与加权分子。该差异本身不能证明下游任务准确率下降。

来源：[PRR 原文 §1、§3、§4.3](https://arxiv.org/html/2606.30389v1#S4.SS3)。论文报告的速度还包含 attention 内核更换的收益；本项目的算法对照应固定底层内核，避免把内核优化和推测收益混在一起。

## 必须保留的强基线

当前官方仓库已有 `flash_attn_with_sparse_block_table_partials()`：为各块保存 FP32 输出及 log-sum-exp，正式选择后仅合并命中块并补算漏块。该接口注释直接描述这一用途。因此“保存全部逐块状态后筛选合并”是已有公开基线，不是本项目的新颖性主张。

来源：[官方 README](https://github.com/Tianyu9748/Incremental_FlashAttention/blob/cfc2c41ffcf395d1f9bb373f4fea0d96e0fe247c/README.md)、[接口源码](https://github.com/Tianyu9748/Incremental_FlashAttention/blob/cfc2c41ffcf395d1f9bb373f4fea0d96e0fe247c/hopper/flash_attn_interface.py#L1018)。第二轮已按此固定提交核查 Python 与 CUDA 路径；逐块入口仍付出内部归并成本，具体约束见 [实现审查](prr_implementation.md)。本项目没有编译运行原仓库全部内核。

本次待验证部分是：只独立保留高 attention 质量块，将其余块聚合；选择完成后丢弃独立误块、从聚合组撤销误块，并通过数值风险检查触发重算。若原型先物化全部逐块状态再压缩，它只能验证算法及压缩后状态大小，不能证明减少了实际峰值内存或首次写回流量。

## 对照和可解释性要求

- 串行严格 Top-K、全部逐块保存、混合撤销和仅推测 KV 预取使用相同选择器与张量布局；PRR 式 union 合并单独标明语义。
- 性能计时覆盖选择、集合运算、分组、重读、合并及回退。计算相对质量阈值所需的前置遍历不能排除在外。并发时应测量选择器受到的资源争用。
- FP64 严格集合参考用于数值误差；最大绝对误差与归一化 L2 同报，避免接近零的输出让相对误差失真。
- 必测高权重误块、多个低权重误块合计占优、带符号 value 的分子抵消、全命中、全失配、空保留集合与非满块。分母剩余比例检查并不能保证各维分子的相对精度。
- 记录回退率、真实分配峰值及可测流量；公式估算的状态大小、KV 读取量必须标为估算。缺少硬件计数器时，不把预取加速解释成已验证的缓存命中率改善。
- GPU 微基准不等于模型端到端解码结果；合成重叠率不等于真实模型预测效果。跨硬件结果只适用于各自实际运行环境。

本项目的候选优化及数值风险分析是根据笔记推导的实验设计，不是对 PRR 论文结论的复述。
