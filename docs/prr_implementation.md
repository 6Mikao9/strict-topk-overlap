# PRR 官方实现审查

审查对象为 `Incremental_FlashAttention` 提交 `cfc2c41`。以下结论来自源码检查，性能与边界行为尚未在本地编译或运行验证。[固定提交](https://github.com/Tianyu9748/Incremental_FlashAttention/commit/cfc2c41ffcf395d1f9bb373f4fea0d96e0fe247c)

## 官方路径实际做什么

- **公开包装器有独立漏块计算和归并。** `flash_attn_speculative_sparse` 先对调用方提供的 `k_spec/v_spec` 做稠密 FA，再根据调用方提供的漏块表读取完整 K/V，随后转换、堆叠两份 `(O,LSE)` 并调用独立的 `fwd_combine`。两份状态的权重均为正，调用方负责使预测块与漏块不交叠。这个包装器顺序调用两个前向，预测构造和双流调度由外部组织。论文 §4.3 描述的流式修复把漏块直接合入已有状态，公开包装器的启动与中间张量成本应按源码计量。[README](https://github.com/Tianyu9748/Incremental_FlashAttention/blob/cfc2c41ffcf395d1f9bb373f4fea0d96e0fe247c/README.md#L88-L106) · [Python 包装器](https://github.com/Tianyu9748/Incremental_FlashAttention/blob/cfc2c41ffcf395d1f9bb373f4fea0d96e0fe247c/hopper/flash_attn_interface.py#L1155-L1219) · [论文 §4.3](https://arxiv.org/html/2606.30389v1#S4.SS3)
- **Hopper 的漏块计算通过稀疏表分派。** C++ 把一维表传入 SM90 TMA/GMMA mainloop，producer 和 consumer 使用同一个分片范围，只访问列表内的 KV tile。普通稀疏入口允许 C++ 选择分片数。若实际分片数大于 1，这次前向内部还会先执行一次 combine。独立 combine 以共同最大 LSE 做稳定的正权重归一化。[SM90 分派](https://github.com/Tianyu9748/Incremental_FlashAttention/blob/cfc2c41ffcf395d1f9bb373f4fea0d96e0fe247c/hopper/flash_fwd_kernel_sm90.h#L355-L372) · [分片范围](https://github.com/Tianyu9748/Incremental_FlashAttention/blob/cfc2c41ffcf395d1f9bb373f4fea0d96e0fe247c/hopper/mainloop_fwd_sm90_tma_gmma_ws.hpp#L78-L101) · [C++ 启动](https://github.com/Tianyu9748/Incremental_FlashAttention/blob/cfc2c41ffcf395d1f9bb373f4fea0d96e0fe247c/hopper/flash_api.cpp#L1241-L1271) · [CUDA 归并](https://github.com/Tianyu9748/Incremental_FlashAttention/blob/cfc2c41ffcf395d1f9bb373f4fea0d96e0fe247c/hopper/flash_fwd_combine_kernel.h#L345-L382)
- **逐块 API 仍付一次内部归并。** `flash_attn_with_sparse_block_table_partials` 令分片数等于块数，返回 FP32 的逐块归一化输出与 LSE，并丢弃常规前向输出。多块时，C++ 仍先归并全部分片，调用方筛选后再归并会重复工作。C++ 最多支持 256 个分片。静态检查还发现单块入口允许传入，但分片数为 1 时 C++ 不分配分片输出，不能假定返回有效的一块状态。[逐块入口](https://github.com/Tianyu9748/Incremental_FlashAttention/blob/cfc2c41ffcf395d1f9bb373f4fea0d96e0fe247c/hopper/flash_attn_interface.py#L1018-L1095) · [分片分配](https://github.com/Tianyu9748/Incremental_FlashAttention/blob/cfc2c41ffcf395d1f9bb373f4fea0d96e0fe247c/hopper/flash_api.cpp#L1166-L1187) · [内部归并](https://github.com/Tianyu9748/Incremental_FlashAttention/blob/cfc2c41ffcf395d1f9bb373f4fea0d96e0fe247c/hopper/flash_api.cpp#L1241-L1271)
- **块表和平台限制会影响对照。** FA-3 稀疏入口使用整个批次和全部头共享的一维 `int32` 表，要求完整历史块，不做因果或局部掩码，也不接受分页 KV。原生 GQA 可以共享 KV，却仍无法用该表表达每个查询头独立的选择。非 128 块长的稀疏专用分派要求 SM90、D=128 和 FP16/BF16。另需核对构建版本，当前 `setup.py` 在 PyTorch 2.9 的指定开发版及之后选择 stable C++ ABI，而该文件的 `fwd` 签名缺少稀疏表参数。[接口约定](https://github.com/Tianyu9748/Incremental_FlashAttention/blob/cfc2c41ffcf395d1f9bb373f4fea0d96e0fe247c/hopper/flash_attn_interface.py#L944-L977) · [CUDA 专用分派](https://github.com/Tianyu9748/Incremental_FlashAttention/blob/cfc2c41ffcf395d1f9bb373f4fea0d96e0fe247c/hopper/flash_api.cpp#L373-L399) · [构建分支](https://github.com/Tianyu9748/Incremental_FlashAttention/blob/cfc2c41ffcf395d1f9bb373f4fea0d96e0fe247c/hopper/setup.py#L588-L597) · [stable 算子签名](https://github.com/Tianyu9748/Incremental_FlashAttention/blob/cfc2c41ffcf395d1f9bb373f4fea0d96e0fe247c/hopper/flash_api_stable.cpp#L1897-L1927)
- **A100 有独立的 FA-2 稀疏路径。** 官方的 SM80 脚本只做编译检查，涉及 FA-3 树中的稠密前向与 combine，Hopper 稀疏 gather 的正式实例仍为 SM90。FA-2 的固定形状 `mha_fwd` 通过 PyBind 扩展 `sparse_flash_attn_2_cuda.fwd` 接受稀疏表，README 所列的 `torch.ops` 入口与此源码不一致。FA-2 强制非 SplitKV，表项对应实际内核的 `kBlockN`，例如 A100 上 D=128、无 dropout 的此分支使用 64-token tile。它不能直接代入本原型的 32-token 逐头选块基准。[SM80 检查](https://github.com/Tianyu9748/Incremental_FlashAttention/blob/cfc2c41ffcf395d1f9bb373f4fea0d96e0fe247c/check_sm80_build.sh#L59-L73) · [FA-2 API 与绑定](https://github.com/Tianyu9748/Incremental_FlashAttention/blob/cfc2c41ffcf395d1f9bb373f4fea0d96e0fe247c/csrc/flash_attn/flash_api.cpp#L1508-L1514) · [FA-2 稀疏调度](https://github.com/Tianyu9748/Incremental_FlashAttention/blob/cfc2c41ffcf395d1f9bb373f4fea0d96e0fe247c/csrc/flash_attn/flash_api.cpp#L459-L506) · [FA-2 D=128 tile](https://github.com/Tianyu9748/Incremental_FlashAttention/blob/cfc2c41ffcf395d1f9bb373f4fea0d96e0fe247c/csrc/flash_attn/src/flash_fwd_launch_template.h#L233-L249)

## 对补充与擦除内核的启发

1. **共用差集的读算路径。** 按查询头确定新增 `A\P` 和擦除 `P\A`，在同一组 block tile 中给它们分配 `+1`、`-1`，共用 QK 与加权 V 计算，跳过交集。没有差集时直接复用预测状态。整组被拒时可以直接丢弃该组。
2. **在同一尺度对分子和分母分别加减。** 预测聚合状态保留 `(m,l,u)`。统一最大值后，新增贡献加到 `l,u`，擦除贡献从两者扣除，最后才做除法。只把 V 取负仍会累加概率分母。官方正权重 combine 不能直接表达擦除。[官方归并权重](https://github.com/Tianyu9748/Incremental_FlashAttention/blob/cfc2c41ffcf395d1f9bb373f4fea0d96e0fe247c/hopper/flash_fwd_combine_kernel.h#L352-L382)
3. **把分片粒度和启动次数分开验证。** 官方的 split 路径通过独立 combine 汇总 CTA 的部分结果。单次修复启动可在一个 CTA 内并行处理块 tile 并归约。在大量漏块时，多 CTA 加一次归并可能更快，应单独比较完整延迟。
4. **保留精确回退。** 在加入漏块之前检查擦除后残留预测质量，避免新增块掩盖消去风险。逐坐标绝对贡献包络有助于识别组内累加丢失小项的情况。用 FP64 严格集合结果验证错块支配、正负 V 消去、零差集和全错预测。回退表示所选集合被重算，数值守卫仍是启发式。
