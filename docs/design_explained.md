# Saved、hybrid 和 compact 为什么耗时不同

设本步选择器给出的 Top-K 块集合为 `A={1,2,3}`，预测块为 `P={1,2,4}`。预测阶段用**本步 Q** 算块 1、2、4 的注意力贡献。上一解码步提供的只有块 ID。选择结束后，块 1、2 的工作可以复用，块 3 需要补算，块 4 是误预测。严格 Top-K 要求结果恰好来自块 1、2、3。

每个块的中间态 `(m,l,u)` 记录块内最大 logit、相对该最大值的指数和、同一尺度下的加权 V 向量。合并多个块时，先把 `l` 和 `u` 缩放到共同的最大 logit，再分别求和并以总 `u / l` 得到输出。这样只需要块状态即可合并，也能在合并之前排除一个块。即使块 4 的 V 是零，它也能通过改变分母来改变输出。[原型的内核与数值约定](KERNELS.md)

| 路径 | 推测结束时持有的状态 | `A` 到达后如何处理 |
| --- | --- | --- |
| `saved` | 为 1、2、4 分别保存 `(m,l,u)`。 | 排除 4，补算 3，合并 1、2、3。每个预测块保留独立状态，所以排除 4 无需再次读它的 KV。 |
| `hybrid` | 先生成全部块状态，再分组。假设 1 质量较高，2、4 较低，则修复时使用 1 的独立状态和 2、4 的聚合态。当前实现还持有完整的逐块状态张量。 | 若同一个低质量组里既有命中又有误预测，就按共同尺度从聚合态里减去低质量错块的贡献。此例重算 4 后扣除，再补算 3。整组都错时直接丢弃。高质量错块可直接排除。 |
| `compact` | 先用 Q/K 求各块的标量 `m,l`，判断质量并打包高质量块 ID。再用 Q/K/V 计算保留的高块向量和一个低组聚合向量。 | 与 hybrid 同样处理漏块和错块，低质量错块在修复阶段聚合后扣除。准备阶段多一次 Q/K 计算，但省掉了低质量块逐个持有的 `u` 向量。 |

这里的质量阈值 `τ` 由预测集合的 softmax 决定。概率质量总和为 1，单块质量至少为 `τ` 的块数最多为 `floor(1/τ)`。实现再留一个应对浮点边界的槽位，并把容量限制在预测块数以内。`ε` 是另一个参数，用于允许近似路径保留部分错块质量。保留的概率质量和输出误差量纲不同，误差还取决于 V。严格路径使用守卫检测低组扣除后的剩余质量与消去，命中守卫的头在所选集合上重算。[容量、储存量与守卫](KERNELS.md) · [第一轮误差实测](results.md)

## PRR 为什么有更多加速空间

PRR §4.3 把预测集合上的注意力聚合成每头一个状态。它保留误预测块，再把遗漏块 `A\P` 合入，所以示例实际参与注意力的是 `1,2,3,4`。这使修复能围绕漏块流式读取 KV，并利用基于 FlashAttention 的在线 softmax。严格路径必须排除块 4，因此要么保留可过滤的逐块状态，要么采用分组扣除。两条路径都覆盖所选集合，最终注意力归一化所用的集合存在差别。[PRR §1、§4.3](https://arxiv.org/html/2606.30389v1)

PRR 论文的内核比较采用 H100、32 个查询头、8 个 KV 头、128K token 上下文和 1K–8K token 注意力预算。其面向 Hopper 优化的 CUDA 内核相对 FlashInfer BlockSparseAttention 平均 2.22×，1K 预算时为 1.03–1.17×。论文的端到端消融中，上一步块预测加漏块时整组重算平均 1.01×，换上定制内核与增量修复后为 1.30×，再启用 EMA 的完整配置在表 2 中为 1.56×。第二步同时改变了内核与修复，因而无法用 `1.30× / 1.01×` 单独归因于修复。[PRR §5.3、§5.4、Limitations](https://arxiv.org/html/2606.30389v1)

PRR 还用历史块分数的 EMA 预测，并根据实测选择窗口调整预测块数。第一轮原型的真实 QKV 回放则取 Qwen3-0.6B-Base 的 2K 上下文，用上一步所选的 8 块预测本步，平均重叠为 78.9%。其计时单位是单层固定张量上的选择与注意力，PRR 还测量了更大模型上完整的长上下文解码。GPU 架构、内核质量、选择窗口、预测策略、注意力预算和计时边界都会改变收益，无法把两组比值直接相减来估计某一项差距。[PRR §4.4、§5.1–5.5](https://arxiv.org/html/2606.30389v1) · [第一轮 QKV 回放](results.md)

## 第一轮原型的开销在哪

- `saved` 为逐块状态写出 FP32 向量，随后做成员匹配和合并。每少读一块命中的 KV，这些固定工作仍需执行。推测和选择还会共用 GPU 执行资源与内存带宽，双流并发下的耗时可超过两者单测的最大值。
- `hybrid` 在完整逐块状态上再增加分组与扣除。`compact` 减少存活状态，但额外执行 Q/K 统计，并让每头的低组聚合顺序遍历候选块。第一轮 compact 的预测状态为 hybrid 的 23.8–101%，全路径 PyTorch allocator 增量峰值在报告精度下相同。额外 K 读量是算法估算，实际 DRAM 流量未测。
- 融合让 CUDA Graph 下 compact 修复 p95 相对原修复提升 1.05–1.60×，完整 compact 仍在所有测点慢于同选择器的串行精确基线。严格融合的两个完整路径加速都来自同一个 100% 重叠合成配置。Qwen 回放的严格和近似路径均未超过串行精确基线。[第一轮融合、显存与回放结果](results.md)

第二轮已把串行精确、严格修复和只补漏的并集路径放在同一套原生 GQA 数据布局、块算术和选择器下。并集对照仍合并逐块状态，没有运行原 PRR 的每头聚合与流式修复内核。另测只执行选择与推测并汇合的路径，它不产出注意力结果，用于估计现有调度去掉修复后的空间。计时在同一 CUDA event 区间内多次回放同一张 Graph，并用相邻基线配对复测。轻量修复在完全命中的合成配置中稳定获益，真实回放所有推测完整路径仍慢于串行精确。[第二轮结果和测量边界](round2_results.md)

## 补充和擦除共用计算内核

漏选块和需从低质量聚合中撤销的错块都要读取 KV、计算 QK、指数权重及加权 V。它们可以进入同一个任务队列，补充任务带 `+1`，擦除任务带 `-1`。符号同时作用于分母 `l` 和分子 `u`。高质量错块的独立状态直接过滤；整组均未命中时直接舍弃聚合组。

旧 `repair_fused` 已在一个启动里处理两类操作，但每个 head 内顺序遍历。新 `signed_fused` 用一个 CTA 处理一个修正块，两种任务共享同一个读算 kernel；任务排布和输出归并是另外两次启动。这样保留块级并行。少量修正时，排布与归并开销可能超过节省的计算，单次启动的旧路径仍可能更快。

负块必须匹配准备阶段的浮点顺序。`hybrid` 先在块内归约再缩放；`compact` 直接在低组尺度计算。直接把 hybrid 擦除也改成低组指数，会在极小权重与大幅值 V 的组合下提前下溢。本项目增加 BF16 反例并匹配各自准备顺序。合并仍先检查低组撤销后的剩余质量和分子消去，再加入漏块；失败时在同一次归并启动内重新计算严格选择集合。

对官方公开包装器与底层 CUDA 的固定提交审查见 [PRR 实现审查](prr_implementation.md)。新的加减融合及相邻基线配对结果见 [专项报告](signed_results.md)。
