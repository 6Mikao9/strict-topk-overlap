# Host-backed KV 缓存的因果轨迹回放

在 CPU 上回放 Qwen/Qwen3-4B 的密集解码轨迹。选中集合来自外接 Quest 风格的块排序。上下文为 [16384, 32768] token，目标层为 [1, 18, 35]，每层每个查询头使用独立的逻辑 GPU 缓存。每个上下文第 0 步只用真实选中块热身。其后 7 步计入结果。[predictor_rank_trace.json](../results/window/predictor_rank_trace.json)

完整 KV 在逻辑 host 存储中可用。缓存按目标层与头独立管理，容量为 K、2K、4K 个块。每个策略和容量都从同一热身状态出发，随后各自演化。基线只按需搬运。候选在本层选择前使用上一解码步同层、当前步前一层，或两份排名交替去重后的前缀。跨层按查询头编号对应，预取目标层的 KV。

只搬运预测列表里尚未驻留的块。预取写入 LRU，排名越靠前，写入后的访问记录越新。已驻留的预测块在需求前保持原有顺序。真实选集到达后，以需求开始前的缓存快照计算全部缺页，再统一填入并按排名更新 LRU。只读 KV 被驱逐时无需回写。模型假定预取在本步选择之前完成，搬运带宽、流依赖和排队时间均未计时。

逻辑块为 32 token × 128 维 × 2 字节 × K/V 两份，即每次 16,384 字节。逐查询头求和可能重复计算 GQA 共享的物理页。这个静态估算描述逻辑 H2D 字节。实测 H2D 时延、HiSparse 的 GPU 缓存行为和原生 QSA 均超出该轨迹的测量范围。[cache_trace.json](../results/hisparse/cache_trace.json)

`覆盖` 与 `污染` 在同一候选当步预取前后的状态上比较。`净少补` 等于独立按需基线缺块减候选需求缺块。额外搬运等于候选预取加需求，再减基线需求。未用预取指当步未被选择，之后仍可能有用。

## 全部上下文和层的配对计数
